# Documentation Guidelines

## Purpose

Define where project information must be documented to keep the repository consistent and easy to navigate.

---

## README.md

The README answers the question:

> How do I use this project?

It should contain:

- Project overview
- Vision
- Technology stack
- Prerequisites
- Installation
- Configuration
- Running the application
- Links to additional documentation

The README evolves incrementally during each sprint.

---

## docs/

The `docs` folder answers the question:

> How is this project built?

It contains:

- Architecture
- ADRs
- Sprint documentation
- API documentation
- Diagrams
- Engineering decisions

---

## Notion

Engineering Project OS (Notion) manages:

- Project planning
- Roadmap
- Sprint planning
- Sessions
- Tasks
- Learning Stories
- Project metrics

---

## Documentation Rule

Before documenting new information, always ask:

> Where would a developer expect to find this information?

The answer determines where it belongs.

Avoid duplicating documentation across README, docs and Notion.
